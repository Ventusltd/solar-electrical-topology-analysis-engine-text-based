# V9 DEBUG MIRROR — GOVERNING AI REVIEW INSTRUCTIONS

All AI systems working on V9 must begin here.

The governing logic is in `v9-sandbox/debug/engine.js`.
The deterministic checks and machine-readable review report are in `v9-sandbox/debug/tests.js`.
The browser shell in `v9-sandbox/app.js` must contain no engineering formula or topology decision.

Before changing code, ask continuously:

1. Is this mathematics physically correct for a solar PV DC string and inverter input arrangement?
2. Is the input the correct physical quantity, especially cell temperature versus ambient temperature, route length versus conductor length, and module centre spacing versus terminal spacing?
3. Does every electrical topology create one valid series path through every module exactly once?
4. Are factory leads, extensions, field-installed home runs and connector interfaces represented separately?
5. Is an estimate clearly labelled as an estimate rather than a construction quantity?
6. Can the same input reproduce the same output exactly?
7. Is every warning generated by the computation engine rather than invented by the renderer?
8. What physical objects or measured parameters are still absent?

Do not add plan view, side view, GIS, animation or decorative SVG logic until the computation report passes and the outstanding assumptions are explicitly accepted.

Every change must update or add a deterministic test. Never weaken a test merely to make new code pass.

Claude review output should state:

- formula or rule reviewed
- physical interpretation
- units
- assumptions
- test vector
- expected result
- observed result
- pass/fail
- engineering concern
- recommended correction

Treat the debug folder as the canonical V9 source until a later version is explicitly promoted.
